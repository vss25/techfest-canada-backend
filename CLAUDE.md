# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Commands

```bash
npm start        # production (node server.js)
npm run dev      # development with hot reload (nodemon server.js)
```

`npm test` runs the unit tests in `test/` (node:test, no database or network). No build or lint scripts.

## Architecture

Node.js + Express REST API using **ES modules** (`"type": "module"` in package.json). MongoDB via Mongoose.

**Entry point:** `server.js` — mounts all routes, configures CORS, connects to MongoDB, and handles the Stripe webhook raw body parser (must stay before `express.json()`).

### Key Models (`models/`)

- **User** — auth, ticket ownership, reset tokens; roles: `user` (attendee) / `admin` (staff) / `volunteer`. `role` is the sign-in / admin panel switch: the console checks role `admin`; the apps' staff sign-in (`POST /api/auth/login {staffOnly: true}`) takes role admin / volunteer or the staff / volunteer person type (`canUseStaffSignIn`); ticket-ID sign-in refuses role admin and volunteer accounts (they use the emailed code or their password); the emailed code works for every account. Everything else in the app (moderation, post removal, report alerts, check-in, contact) comes from person types + the app rights matrix (see `/api/console/app-rights`). Person types: `User.types` (set by staff) and `User.typesOff` (the only way to switch an automatic type off for one person); six types since Oct 19 2026 (VIP is the `User.vip` flag: kind "vip" for the apps, no rights of its own; `PATCH /api/console/users/:id {vip}`); effective types (`effectiveTypes` in `services/teamRoles.js`) = (types ∪ automatic) − typesOff, automatic = `staff` (role admin), `volunteer` (role volunteer), `speaker` (holding a Speaker Pass: ticket type `speaker` or promo SPEAKER), `exhibitor` (an exhibitor pass), and `attendee` for anyone holding a ticket or pass who has no other type (so a VIP or vendor with a pass gets only their own column unless staff add Attendee). `PATCH /api/console/users/:id` takes `types` / `typesOff` (lists of the seven types, else 400; giving or removing staff / volunteer is management only; audited with before → after); `GET /api/console/users/:id` adds `types`, `typesOff`, `autoTypes [{type, from: role\|pass}]`, `holdsPass`, `effectiveTypes`, `rights`; `GET /api/console/users` rows carry effective `types` and take `?type=`. Console role values: `user | admin | volunteer` (`PATCH /api/console/users/:id`, management; making someone staff starts them at `staffRole: "staff"`, any other role clears it). `POST /api/console/staff {email, name, password, role: "admin" (default) | "volunteer"}` adds either (audited `staff_add`/`staff_promote` or `volunteer_add`/`volunteer_set`); `GET /api/console/staff` lists both with `role` (volunteers have `staffRole: ""`). ## Catalyst Awards jury (Oct 20 2026)

The organiser: jurors sign in at thetechfestival.com/awards/jury-admin, see the nominations staff allocate to them and score each in about 5 minutes; drafts save, submitted assessments can be edited until the deadline; phone first. - **Jurors are not Users** (`models/Juror.js`): least privilege by construction. Jury tokens are JWTs signed with `JURY_JWT_SECRET`, else an HMAC of `JWT_SECRET` (`jurySecret`), audience `ttfc-jury`, issuer `ttfc-jury-portal`, `typ: "jury"`, `sub` = juror id, `tv` = `Juror.tokenVersion` (bumped on a password change, switching off, removal, an email change), 7 days.
